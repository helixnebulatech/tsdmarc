# tsdmarc architecture

tsdmarc is a 1:1 TypeScript port of [parsedmarc](https://github.com/domainaware/parsedmarc) 11.2.1 and the parts of [mailsuite](https://github.com/seanthegeek/mailsuite) 2.3.4 that parsedmarc uses. Behavior, log messages, error types and output content match parsedmarc. The deliberate differences are listed under [Differences from parsedmarc](#differences-from-parsedmarc).

## Packages

The layout follows the Vercel AI SDK: one core package plus one package per integration, so users install only what they use.

| Package | Contents | Ported from |
| --- | --- | --- |
| `tsdmarc` | Parsing, enrichment (DNS, GeoIP, reverse DNS map, PSL), CSV/JSON output, Maildir, Splunk, syslog, GELF, webhook, Grafana Loki, parallel parsing, the mailbox base class | `parsedmarc/__init__.py`, `utils.py`, `config.py`, `log.py`, `types.py`, `splunk.py`, `syslog.py`, `gelf.py`, `webhook.py`, `loki.py`, `parallel.py`, `mailsuite.mailbox.base`, `mailsuite.mailbox.maildir` |
| `@tsdmarc/imap` | IMAP mailbox connection (imapflow) | `mailsuite.mailbox.imap`, `mailsuite.imap` |
| `@tsdmarc/gmail` | Gmail API mailbox connection | `mailsuite.mailbox.gmail` |
| `@tsdmarc/msgraph` | Microsoft Graph mailbox connection (fetch + @azure/identity) | `mailsuite.mailbox.graph` |
| `@tsdmarc/smtp` | Send emails over SMTP (nodemailer), `emailResults()` | `mailsuite.smtp`, `parsedmarc.email_results` |
| `@tsdmarc/elasticsearch` | Elasticsearch output (client v9): dated indexes or data streams (`useDataStreams`) | `parsedmarc/elastic.py` |
| `@tsdmarc/opensearch` | OpenSearch output: dated indexes or data streams (`useDataStreams`) | `parsedmarc/opensearch.py` |
| `@tsdmarc/postgres` | PostgreSQL output (pg) | `parsedmarc/postgres.py` |
| `@tsdmarc/kafka` | Kafka output (@platformatic/kafka) | `parsedmarc/kafkaclient.py` |
| `@tsdmarc/s3` | Amazon S3 output | `parsedmarc/s3.py` |
| `@tsdmarc/loganalytics` | Azure Log Analytics output | `parsedmarc/loganalytics.py` |
| `@tsdmarc/ipinfo-lite` | The IPinfo Lite MMDB file, for offline GeoIP | `parsedmarc/resources/ipinfo` |
| `@tsdmarc/cli` | The `tsdmarc` command | `parsedmarc/cli.py` |

Integration packages declare `tsdmarc` as a peer dependency (so an application gets one core: one logger, one set of caches) and import from it by package name (`import { logger } from 'tsdmarc'`); the core never imports them. `@tsdmarc/cli` depends on everything normally. `packages/search-common` (`@tsdmarc/search-common`, private, never published) holds the document, DSL, IP and Python-helper code shared by `@tsdmarc/elasticsearch` and `@tsdmarc/opensearch`; tsdown bundles it into both. Every published tarball carries the repo's `LICENSE` and `NOTICE` (copied by `tools/license-files.mjs` at `prepack`), except `@tsdmarc/ipinfo-lite`, which ships its own CC BY-SA 4.0 `LICENSE` and `NOTICE`; `pnpm pack:check` verifies the tarballs. `tools/` holds the shared tsconfig and tsdown setup; `fixtures/` holds parsedmarc's own output for every file in `samples/`.

Outputs added in parsedmarc 11.2: the Grafana Loki output lives in the core (`LokiClient`, `outputs/loki.ts`; only `fetch`, so no separate package), and the Elasticsearch/OpenSearch packages can write each report type to one data stream instead of dated indexes (`useDataStreams` in `SaveOptions`, `createDataStreams()`; the stream is named like the index without its date, and its index template composes an optional `<name>@custom` component template for an ILM policy on Elasticsearch, while an OpenSearch ISM policy attaches itself through its `ism_template`). Every saved document carries `@timestamp` in both modes.

## Conventions

### API shape

- Python `snake_case` names become `camelCase` (`parse_aggregate_report_xml` → `parseAggregateReportXml`); classes keep their names (`InvalidAggregateReport`, `KafkaClient`).
- Keyword arguments become one options object. Positional required arguments stay positional.
- Anything that does network, DNS or disk I/O is `async`. Pure parsing stays sync when Python's is and nothing below it needs I/O; if a function calls something async (e.g. `getIpAddressInfo()`), it is async.
- Public parsing functions accept the individual parser options or `config`, resolved with `resolveParserConfig()`, exactly like parsedmarc's `_resolve_config()`.
- Backward-compatible aliases parsedmarc keeps (`parseForensicReport`, `InvalidForensicReport`, ...) are kept.

### Data keys

- Report objects use camelCase keys (see `types.ts`). Every key maps 1:1 to parsedmarc's snake_case key.
- Outputs (JSON files, CSV headers, Elasticsearch/OpenSearch documents, Splunk/Kafka/S3/webhook/Log Analytics payloads, Postgres columns, syslog/GELF fields) use parsedmarc's snake_case names. Convert whole reports with `toSnakeCaseKeys()`. Email header names under `headers` are data and are never converted.
- Header-derived keys of a parsed email (`x-mailer`, `message-id`) stay as mail-parser names them; `toSnakeCaseKeys`/`toCamelCaseKeys` leave keys without `_` or capitals unchanged.
- Reporter data that parsedmarc passes through untouched (a policy override reason dict, an unknown `<identifiers>` child, an element with attributes or children where text was expected, an SMTP TLS `contact-info` object) is branded with `markRaw()`; objects that mix known fields with reporter keys are built with `mixedObject()`. Key conversion never renames anything inside raw data, so `<toString>` stays `toString` and `<envelopeFrom>` doesn't overwrite `envelope_from`. The brands are non-enumerable symbols, so a structured clone (worker threads) drops them.
- Python ints are unbounded: an aggregate `count`, `original_timespan_seconds` or an SMTP TLS JSON integer beyond ±2^53 is a `bigint` (safe values stay numbers). Serialize reports with `pyJsonDumps()`, not `JSON.stringify()`.

### Python semantics that must be preserved

- **Datetimes:** use `PyDateTime` wherever Python uses `datetime`. Naive values are local time (`process.env.TZ`); aware values carry an offset. `toString()` matches `str(datetime)`, `isoformat()` matches Python's.
- **`str()` of values:** CSV and some payloads print Python values: `True`/`False`, `None` as an empty CSV cell, ints without `.0`, floats with Python's `repr`. Match the fixtures.
- **Regexes:** Python `re` on `str` is Unicode-aware: `\w`, `\d`, `\s` match non-ASCII. In JS use the `u` flag and `[\p{L}\p{N}_]` (or `\p{Nd}`) where non-ASCII matters. Python's `$` also matches before a trailing newline; `re.MULTILINE` is the `m` flag. Follow parsedmarc's anti-backtracking rules (`upstream/parsedmarc/AGENTS.md`, "Regular expressions on untrusted input") and keep its time-bound regression tests.
- **Dicts:** Python dict iteration order is insertion order, like JS objects/Maps; keep the same insertion order so outputs read the same.
- **Bytes vs text:** Python `bytes` → `Uint8Array`/`Buffer`; decode with `TextDecoder` (`fatal` when Python decodes strictly, `replace` when it uses `errors="replace"`).

### Errors and logging

- Raise the same error classes as parsedmarc (`errors.ts`, plus each module's own like `KafkaError`). Messages keep parsedmarc's wording, with "parsedmarc" replaced by "tsdmarc" only where it names the product.
- Log through `logger` from `./log` (or `getLogger(name)` for the syslog/GELF loggers) with the same level and message text as parsedmarc. `logger.exception(message, error)` replaces Python's `logger.exception`.

### Security

- Every input is untrusted: decompression is capped at 100 MiB, XML is parsed without entity expansion, network calls have timeouts, TLS verification is on unless the user turns it off, secrets never reach logs.

## Tests

- Vitest, colocated as `*.test.ts` next to the module. Each parsedmarc/mailsuite test module is ported to the matching TypeScript module's test file; keep test names recognizable.
- Same standards as parsedmarc (`upstream/parsedmarc/AGENTS.md`, "Testing standards"): mock only at SDK boundaries (`vi.mock('@elastic/elasticsearch')`, a fake `fetch`, ...), assert on what is sent, no tests that only check a mock was called.
- Fixture tests compare tsdmarc's output, converted with `toSnakeCaseKeys()`, against `fixtures/**/*.json` (parsedmarc's output, generated offline with `TZ=UTC`).
- Timezone-sensitive tests use `withTz()` / `forceTz()` from `src/test/tz.ts`.
- Network is never required: DNS and HTTP are faked in tests, and parsing runs `offline` where parsedmarc's tests do.

## Differences from parsedmarc

1. Elasticsearch output uses the v9 client (parsedmarc pins `<9`).
2. The API is camelCase; output content is unchanged.
3. Environment variables are `TSDMARC_*`, and `PARSEDMARC_*` is still accepted (`TSDMARC_*` wins).
4. Mailbox connections expose `kind` instead of relying on `instanceof` checks across packages, and have `close()`.
5. JSON output is equal in content to parsedmarc's, not byte-for-byte (non-ASCII is not `\u`-escaped). The JSON files of `appendJson()`/`saveOutput()` do match `json.dump(..., ensure_ascii=False, indent=2)` byte for byte, including existing entries (big ints, `1.0`, `NaN`).
6. Kafka with a username/password uses TLS + SASL PLAIN as parsedmarc documents. parsedmarc sets `security_protocol="SSL"`, so kafka-python silently skips SASL and never authenticates.
7. Kafka and PostgreSQL clients connect lazily; call `KafkaClient.create()` / `PostgreSQLClient.create()` (or `connect()`) to fail at startup like Python's constructors. The PostgreSQL client runs its transactions one at a time (they share one connection, like psycopg's).
8. Splunk's `host` field uses `os.hostname()` (no synchronous FQDN lookup in JS). HTTP timeouts (Splunk, webhook) bound the whole request rather than each phase.
9. IMAP uses imapflow: connecting is async (`IMAPConnection.connect()`), OAuth2 picks OAUTHBEARER or XOAUTH2 itself, and imapflow prefixes the personal namespace to folder paths (shared-namespace paths may be affected). Messages are fetched with `BODY.PEEK[]` and then flagged `\Seen`, matching Python's RFC822 fetch. STARTTLS follows mailsuite 2.3.4 (credentials are never sent before the upgrade unless `starttls: false`), through imapflow's `doSTARTTLS` with mailsuite's checks run before login.
10. `@tsdmarc/smtp` ports only what parsedmarc uses from `mailsuite.smtp` (no DKIM signing, no SMTP OAuth2, no custom headers or HTML). Messages are built by the core's `createEmail()` (a port of `mailsuite.utils.create_email`, shared with `@tsdmarc/gmail`) and sent with nodemailer's SMTP connection.
11. Mailbox backends log to the core `tsdmarc` logger instead of `mailsuite.*` loggers.
12. Microsoft Graph: persistent token caching (DeviceCode) needs the optional peer `@azure/identity-cache-persistence` (native modules); when it is not installed or fails to load, tokens are cached in memory with a warning that says which. Certificate auth reads PEM only. `UsernamePassword` is deprecated by Azure (ROPC; it fails with MFA). It is implemented with `fetch` because @azure/identity for Node has no confidential-client version: like mailsuite's MSAL setup, it sends `client_secret` when one is given, uses the `organizations` tenant, signs in on every connect, and saves the AuthenticationRecord to `token_file` in Python's format (Python reads that file back for this method but ignores it). Its tokens stay in memory (no msal-extensions cache file), and federated (ADFS / WS-Trust) accounts, which Python's MSAL supports through user realm discovery, are not supported. Graph URLs must be https and paging links to other hosts are refused.
13. Gmail: the installed-app OAuth flow is a local loopback server with PKCE and a `state` check (replacing google-auth-oauthlib's `run_local_server`); `token.json` keeps Python's format and is always written with mode 0600 (a new 0600 file atomically replaces the old one); mailsuite writes it with the process umask. The sign-in URL goes to the `google_auth_oauthlib.flow` logger and is printed once.
14. DNS: plain DNS goes through `node:dns` (c-ares), DoH through `fetch` and DoT through `node:tls`, with a port of dnspython's resolver loop (failover, back-off, error classes). Each plain-DNS query is bounded by its own timer at exactly the configured timeout. Queries to a scoped IPv6 nameserver (`fe80::1%eth0`, whose scope c-ares drops) and, on Bun, TXT/CAA queries (Bun's c-ares binding decodes them as UTF-8) are sent as wire-format UDP with a TCP retry on truncation, like dnspython. Wire format uses dns-packet, which decodes labels as UTF-8: a PTR name with non-UTF-8 bytes or a literal dot in a label prints differently from dnspython's `\DDD` / `\.` escapes. Non-ASCII names are checked against IDNA 2008's code point classes (from `idna` 3.20) with idna's messages (`IDNAException`); the UTS 46 mapping comes from `domainToASCII`, and Bidi-rule failures give a generic message instead of idna's.
15. HTTP downloads (IP database, reverse DNS map, PSL overrides, IPinfo API, DoH) use `fetch`. Proxies from `HTTP(S)_PROXY` apply only with `NODE_USE_ENV_PROXY=1` (Node) — httpx always honors them; custom CAs go in `NODE_EXTRA_CA_CERTS` instead of `SSL_CERT_FILE`. Downloads are size-capped, only http(s) URLs are fetched, and the IPinfo token is stripped from logged URLs. `.text` decodes like httpx (Content-Type charset when Python knows it, else UTF-8 keeping a BOM).
16. The IP database reader is reused while the file is unchanged (parsedmarc reopens it per lookup). Downloads are cached per user in `$XDG_CACHE_HOME/tsdmarc`, `~/.cache/tsdmarc` or `%LOCALAPPDATA%\tsdmarc` (fallback `<tmpdir>/tsdmarc-<uid>`), a 0700 directory that must not be a symlink or belong to another user, written through a unique temp file and `rename` — parsedmarc uses a shared `<tmpdir>/parsedmarc` with a fixed `.tmp` name. `configureIpinfoApi()` is async. Reloading the reverse DNS map or the PSL overrides builds the new data aside and swaps it in, so concurrent lookups keep seeing the old data (parsedmarc clears it before downloading), and concurrent reloads share one download.
17. Elasticsearch: the v9 client sends `compatible-with=8` headers by default (option `compatibleWith`), so it works with Elasticsearch 8 and 9 servers. The JS clients send `/_bulk` (Elasticsearch), `/{index}/_mapping` and `/_index_template/{name}` (OpenSearch) as POST where the Python clients use PUT; servers accept both. `reindex()` (scroll + bulk) is ported from the Python helper. Mappings and documents reproduce the Python DSL output exactly (empty values dropped, `pct` as a number, IPs normalized). The shared document, DSL, IP and Python-helper code lives in the private workspace package `@tsdmarc/search-common`, bundled into both published packages. `setHosts()` replaces the default connection without closing the previous client, like the Python DSL connection registry; on shutdown call `await getDefaultConnection()?.close()` and `setDefaultConnection(null)`.
18. OpenSearch: like opensearch-py, a client-level `apiKey` is not sent. Retries follow opensearch-py (3 retries on connection errors and HTTP 502/503/504, none on a timeout) through a transport wrapper, because opensearch-js would also resend timed-out requests. `timeout: null` disables the request timeout and a timeout ≤ 0 raises `ValueError`, as in Python. The AWS SDK is loaded only for SigV4.
19. Email parsing does not use postal-mime (the plan listed it): parsedmarc's output depends on Python's `email` package (compat32 parser, defects, header folding, `decode_header`, RFC 2231, `Generator`) and on mail-parser 4.8.0, so both are ported (`utils/py-email/`, `utils/mailparser/`), with Python's codecs (`utils/py-codecs*.ts`). UTF-7/8/16/32, ASCII, Latin-1, raw-unicode-escape, every charmap codec and the CJK codecs big5, cp950, big5hkscs, gb2312, gbk, gb18030, hz, euc_kr, cp949, euc_jp, shift_jis, cp932, iso2022_jp, iso2022_jp_1 and iso2022_jp_ext decode exactly like CPython (its own tables, the same error ranges, messages and error handlers) on every runtime. The JIS X 0213 codecs (euc_jis_2004, euc_jisx0213, shift_jis_2004, shift_jisx0213, iso2022_jp_2004, iso2022_jp_3) and iso2022_jp_2 are approximated with `TextDecoder`; iso2022_kr, johab, idna, punycode and unicode_escape are unknown (`LookupError`, so the callers' fallbacks apply). Message nesting is capped like CPython's recursion limit for a top-level call: `messageFromString` raises `RecursionError` beyond 987 nested parts and `MailParser.fromString` raises `MailParserRecursionError` beyond 983 (in Python the exact depth depends on the caller's stack depth; `parse_report_email`'s lower limit is emulated separately, see 36). `createEmail()` output matches mailsuite's `create_email()` byte for byte apart from the random boundary and the Date. `parseEmail`, `isMbox` and `convertOutlookMsg` are async; `msgconvert` runs with a 60 s timeout and its output is discarded like `subprocess.DEVNULL`; `isMbox` does not create a missing file.
20. `getReportZip()` leaves out the `../<name>` copies of the samples that parsedmarc's `add_subdir()` adds (its `relpath` arguments are swapped): they point outside the extraction directory. Every file is still in the zip once.
21. Syslog: `SyslogClient.create()` connects up front with the configured retries; save methods are async. The `timeout` also bounds the TCP connect and TLS handshake. Bytes on the wire match Python's `SysLogHandler`.
22. GELF over TLS verifies certificates by default against the system CAs (pygelf doesn't); pass `tls: { validate: false }` for parsedmarc's behavior. The CLI's `[gelf]` section adds two keys for `mode = tls` (ignored otherwise): `cafile`, a CA bundle added to the system CAs (`tls.caCerts`), and `skip_certificate_verification = true` (`tls.validate: false`), also settable as `TSDMARC_GELF_CAFILE` / `TSDMARC_GELF_SKIP_CERTIFICATE_VERIFICATION` (or the `PARSEDMARC_` names). Packets match pygelf's, including the `_parsedmarc` field and `short_message` texts that Graylog dashboards query.
23. `getDmarcReportsFromMailbox()`: `since` is a string (or null); `saveCallback` may return a Promise (a rejection counts as unsaved); `watchInbox()` accepts an AbortSignal. Kept from parsedmarc on purpose: Gmail's `since` is computed with `strftime("%s")` semantics (off by the local UTC offset outside UTC), and the `batchSize: 0` re-check runs with parsedmarc's defaults.
24. Parallel parsing (`parallelMap`) runs named tasks in `worker_threads` instead of pickled functions; the config crosses threads as `parserConfigToState()`. No tqdm progress bar.
25. CLI: `main(argv)` throws `SystemExit` instead of exiting so cleanup runs; `bin.ts` turns it into the exit status (usage errors 2, `--help`/`--version` 0, uncaught errors 1). Output clients and mailbox connections are always closed on exit (an open socket keeps Node running). `--dns_timeout` is accepted and rewritten to `--dns-timeout`. The default SMTP subject and startup line say `tsdmarc`; the Graph token cache name stays `parsedmarc` so existing caches keep working. Console log lines are `LEVEL:tsdmarc:message` (no file/line numbers in JS).
26. CLI config: `TSDMARC_*` and `PARSEDMARC_*` environment variables are both read (`TSDMARC_*` wins, `_FILE` variants included; `TSDMARC_DEBUG` is an alias of `DEBUG`). `[kafka] ssl` is passed to the client (parsedmarc parses it but never uses it). The index-prefix map YAML is read as YAML 1.1 like PyYAML. Duplicate file arguments keep their order.
27. CLI watch mode: SIGHUP, SIGTERM and SIGINT also abort the running `watchInbox` through its signal, so it returns without waiting out `check_timeout`. Azure SDK logs go to a `tsdmarc` logger named `azure`. Progress is a simple stderr bar instead of tqdm. There are no optional extras, so parsedmarc's "install the extra" hints don't exist.
28. PostgreSQL uses pg instead of libpq, with libpq's rules rebuilt on top: connection strings (URI or `key=value`) are parsed like libpq; values fall back to the `PG*` variables and libpq's defaults. Without a host it connects to the Unix socket (`PGHOST`, else `/var/run/postgresql`, or `/tmp` if only that socket exists). `sslmode` follows libpq (default `prefer`; `~/.postgresql/root.crt` and client certificates are used, and `verify-*` without a root certificate fails). `prefer`/`allow` reconnect instead of falling back on the same socket, and don't retry when the server is unreachable. The connect timeout follows psycopg (`connect_timeout`, then the `connectTimeout` option, then `PGCONNECT_TIMEOUT`, then 130 s; minimum 2 s). TCP keepalive is on. libpq options pg can't honor (e.g. `hostaddr`, `target_session_attrs`) are ignored with a warning, the ones that demand a protection pg can't enforce are refused (see 67), and several hosts in `host` are refused. `PostgreSQLClient` also takes `sslmode`, `sslrootcert`, `sslcert` and `sslkey` options when no connection string is given.
29. S3: like boto3, 60 s connect and 60 s idle-read timeouts; the default-region lookup runs once per client. Log Analytics: each HTTP attempt (upload chunks, retries, token requests) gets azure-core's 300 s timeout as a single per-request limit (the JS pipeline has no separate connect and read timeouts). Gmail token refreshes send `scope`, like google-auth.
30. IMAP reconnects (`resetConnection()`, run before retrying a timed-out fetch, move, delete or folder creation, and by the IDLE loop) re-select the folder that was selected before, not `initial_folder`: mailsuite re-selects INBOX, so its retried move/delete applies the reports folder's UIDs to INBOX. The IDLE loop is also marked active before its first callback, so a reconnect inside that callback can't start a nested loop. `timeout` behaves like imaplib's socket timeout (it only runs while a command waits for the server; an idle connection never times out), enforced by a watchdog on imapflow's byte counters, because imapflow's own `socketTimeout` also closes quiet idle connections and breaks IDLE.
31. Dates: `parseDate()` is a port of dateutil 2.9.0's parser (checked against a 9,428-string differential corpus in six time zones). Differences: local zone abbreviations come from ICU's English short names, so zones ICU has no English abbreviation for (JST, China's CST, MSK, PKT, Israel's IST/IDT) stay naive where Python would apply the local zone; "DST" means "at the zone's DST offset" (JS has no `tm_isdst`); the local zone is read per call; offsets of 24 h or more and Python's `OverflowError` raise `RangeError` at once; letter/digit classes follow the JS engine's Unicode tables.
32. Report parsing reproduces parsedmarc's evaluation order and Python 3.14's exception messages (`list indices must be integers or slices, not str`, `argument of type 'NoneType' is not a container or iterable`, `cannot use 'dict' as a set element (unhashable type: 'dict')`, `sequence item 0: expected str instance, dict found`, `timestamp out of range for platform time_t`, `year must be in 1..9999, not N`). For timestamps far outside JS `Date`'s range (beyond ±8.64e12 s) the year in that message is computed in UTC; Python uses local time, which differs only within the UTC offset of New Year.
33. `_bucket_interval_by_day` gives the same buckets and counts as parsedmarc, but works per group of days with the same overlap instead of looping over every day, so a reporter-supplied `date_range` spanning millennia costs time proportional to the buckets it produces; the day layout is computed once per report (`IntervalDays`). The number of buckets is also capped (see 52).
34. `parseAggregateReportFile(string)` treats the string as report content (base64, or the XML itself), as parsedmarc's `parse_aggregate_report_file()` does despite its docstring; `parseAggregateReportFromFilePath()` reads a file.
35. `pyJsonLoads()` (SMTP TLS JSON) takes a `maxDepth`, checked while scanning rather than on the finished tree, so deep input never fills the heap; without it any depth is accepted. Python's `json.loads` raises `RecursionError` at a depth set by its C stack (over 2,000 levels in Python 3.14). SMTP TLS reports use 512 (see 39).
36. Python's recursion limit is emulated where parsedmarc hits it on deeply nested input: when `str(part)` would flatten more than 246 nested multipart or message parts (Python 3.14 fails at a chain of 248, as a call from a module's top level does), `parseReportEmail()`/`parseReportFile()` throw `ParserError('Unable to parse message with subject "...": maximum recursion depth exceeded')` with a `RecursionError` as its cause, like parsedmarc 11.1.0. In Python the limit moves down one level for every four frames of caller stack, so deeper call sites fail slightly earlier.
37. `extractReport()` reproduces Python's `zipfile` and `zlib` exactly, error messages included: the zip reader is a port of CPython 3.14's `zipfile` read path, and inflate, bzip2, LZMA and Zstandard (zip methods 8, 12, 14, 93) are pure-TypeScript ports of zlib 1.3, libbzip2, liblzma and libzstd 1.5.7 (`src/internal/`), so no native module is needed. Two differences: every member is bounded by the 100 MiB cap while decompressing (Python's zip reader bounds only the output it returns, so a bzip2/LZMA/Zstandard member past the cap fails here with the size-limit error where Python would go on to a later error), and legacy Zstandard frames (formats v0.5-v0.7), which Python decodes through the system libzstd, are not supported.
38. An aggregate report whose data nests more than 512 objects/arrays deep is rejected with `InvalidAggregateReport` (`Invalid XML: report data nested more than 512 levels deep`). parsedmarc keeps some reporter elements verbatim (unknown `<identifiers>` children, dict-shaped fields), and `JSON.stringify()`, `structuredClone()` (worker threads) and SDK serializers recurse, so deeper data would overflow the call stack in the outputs; Python accepts it (its `json.dumps` fails only at about 150,000 levels). libxml2's recovering parser already caps nesting at 256 elements, and other deep XML that parsedmarc discards is still accepted. `pyJsonDumps()`, `pyRepr()` and `toSnakeCaseKeys()`/`toCamelCaseKeys()` are iterative and handle any depth.
39. An SMTP TLS report (JSON) whose data nests more than 512 objects/arrays deep is rejected with `InvalidSMTPTLSReport` (`report data nested more than 512 levels deep`), for the same reason. The depth is checked while scanning (as a tree, 100 MiB of `[` took over 2 GB of heap), so a too-deep report fails with that message even when it also has a JSON syntax error further on or lacks a required field. Python's `json.loads` raises `RecursionError` only past 2,000 levels (wrapped the same way), and between those depths parsedmarc accepts the report.
40. **Credentials in logged URLs.** As in parsedmarc 11.2, logged URLs go through `redactUrlCredentials()` (`https://user:***@host`; a userinfo without `:` becomes `***@`): the CLI's `Initializing Elasticsearch/OpenSearch client: hosts=[...]`, `Initializing Splunk HEC client` and `Initializing Loki client` lines, OpenSearch's `Connecting to OpenSearch` line, the core's `Trying to fetch ... from <url>` lines and download warnings, and Loki push errors; DNS errors and the CLI's DNS pre-flight go through `maskNameserverSecrets()`; a malformed Splunk, webhook, Loki or download URL and a malformed PostgreSQL `connection_string` give parsedmarc's fixed `(details withheld because they may include credentials)` messages. What tsdmarc does beyond that: `redactUrlCredentials()` always masks from the start of the authority through the last `@` of the whole string when that `@` is not inside the authority, also when the authority has its own `@`, so `https://user:p@ss/word@host` logs as `https://***@host` and `https://a:b@host/?redirect=https://u:p@evil` as `https://***@evil` (parsedmarc masks only the authority's userinfo there, keeping `ss/word` and the credentials in the query); the CLI's `Initializing Kafka client: hosts=[...]` line is masked too (parsedmarc logs it as given); the `Trying to fetch IP database / reverse DNS map / PSL overrides from <url>` debug lines also drop the query string and fragment, since IPinfo's download URL carries `?token=`. `fetch` refuses URLs with `user:password@` and quotes them in its error, so HTTP downloads, DoH and the Splunk/webhook/Loki clients send those credentials as `Authorization: Basic`, as httpx does; `HTTPStatusError`, DoH's `responded with status code` and `DoHNameserver.toString()` (and so `LifetimeTimeout` and `NoNameservers`) print the masked URL. The `HTTP <status> for url '<url>'` line of a failed download drops the query string (parsedmarc keeps it, and masks the IPinfo `token` only in httpx's own `HTTP Request:` log lines, which tsdmarc doesn't have), a URL quoted in a download's transport error loses its query string (Deno quotes the whole URL, IPinfo token included), and everything the Splunk/webhook `httpPost()` throws, causes included, keeps only a URL's scheme and host (a webhook URL often is the credential).
41. **DoT without a hostname.** A `tls://ip[:port]` nameserver without `#hostname` logs a warning once per entry (only the certificate chain is verified, so any server with a publicly trusted certificate can answer); behavior is otherwise unchanged (dnspython also checks only the chain).
42. **HTTP requests and responses (Splunk HEC, webhook, Loki).** A header value with a NUL, CR, LF or a character above U+00FF (for example a HEC token with a line break) is refused before sending with `Invalid value for the <name> header`; httpx raises its own error (h11's quotes the value), and `fetch` would quote the value, which is a token. Response bodies (Splunk HEC, webhook) are read only when needed and capped at 1 MiB (`MAX_RESPONSE_BYTES`) on both the `fetch` path and the `verify = false` `node:https` path; a larger Splunk response fails with `SplunkError("Response body exceeds 1048576 bytes")` instead of being buffered and parsed. httpx reads any size. The webhook client discards (cancels) the unused response body right away, and redirect bodies are never read.
43. **Search failure-report headers.** Elasticsearch and OpenSearch copy the sample's headers as own properties, so a header named `__proto__` (or `constructor`) is kept in the document like in Python's dict; the shared DSL serializer does the same for every document key.
44. **CSV formula escaping can be turned off.** Like parsedmarc 11.1.0, text cells starting with `=`, `+`, `-`, `@`, a tab or a carriage return get a leading `'` (after the NUL strip; numbers are never changed). tsdmarc adds a switch parsedmarc doesn't have: `csvFormulaEscape: false` in `saveOutput()`/`getReportZip()`, `{ formulaEscape: false }` in `parsed*ReportsToCsv()`, `rowsToCsv()` and `CsvDictWriter`, or `[general] csv_formula_escape = false` in the CLI (`TSDMARC_GENERAL_CSV_FORMULA_ESCAPE`) write cells unchanged. `csvFormulaEscape()` is exported.

46. Size limits (parsedmarc has none). `ParserConfig.maxEmailSize` (default 50 MiB, `0` = no limit) and `maxMimeParts` (default 10,000 lines starting with `--` after LF or CR, an upper bound on MIME parts; `0` = no limit), checked in linear time before parsing; the parser also counts every `Message` it creates against `maxMimeParts` (parts without a boundary line, such as the one `message/delivery-status` makes per blank line: 20 MiB of newlines used to exhaust a 2 GiB heap), and two more limits apply while parsing: `maxHeaderLines` (default 100,000 over all parts, folded lines and lines that only produce defects included) and `maxExpandedEmailSize` (default 512 MiB of characters re-serializing nested parts may produce, size × depth, in `parseReportEmail()`'s walk and in mail-parser's attachments; text with a character beyond Latin-1 counts each character twice, since it takes two bytes per character: CJK text nested hundreds of levels deep held 2 GB of heap from a 3 MB email, about 1 GB at most now). These also apply to a failure report's sample and to `parseEmail()`/`MailParser.fromString()`, with the defaults when no limits are given, and the parser reads lines on demand so they fire before one string per line exists; over either, `parseReportEmail()` throws `EmailTooLargeError` (a `ParserError`). Mailbox backends get the limit as `fetchMessage(id, { maxSize })` and refuse a larger message before downloading it where they can: IMAP fetches `RFC822.SIZE` first and, since that is only the server's word, also holds the limit while reading (`limitedCommand()`; mailsuite downloads the whole message): imapflow's response limits are lowered to `maxSize` for the fetch, so a literal over it is refused at its `{n}` marker (imapflow closes the connection and tsdmarc reconnects), the chunked `download` fallback stops at `maxSize + 1` bytes, and the bytes received for the whole FETCH are capped at `maxSize` + 1 MiB (a server answering one FETCH with many rows); such a message is refused with `EmailTooLargeError` and not marked `\Seen`. Microsoft Graph checks `Content-Length` and stops reading past the limit, Maildir and mbox check the file/message size; Gmail returns the content with `sizeEstimate`, so it is checked after the (Gmail-capped) download. Like a content error while fetching, the message is then moved to the invalid folder (not marked read), with the warning `Message UID <id>: Email of <n> bytes exceeds ...`. `getDmarcReportsFromMbox()` skips such a message with a warning (`Skipping message <n>: EmailTooLargeError: ...`), like any other `ParserError` (see 56). Besides the 100 MiB cap per attachment, the attachments of one email may decompress to at most 100 MiB together: once an attachment that is not a report takes the total past it, the email is refused with `EmailTooLargeError` (`Email attachments decompress to more than 104857600 bytes`); a report found in an attachment is always parsed (parsedmarc decompresses every attachment until it finds a report). `parseReportFile()` refuses a file larger than `max(maxEmailSize, 100 MiB)` without reading it, and stops reading a stream past it (the stream is left open for the caller). The `sample.eml` that `msgconvert` writes for an Outlook MSG file is checked against `maxEmailSize` and `maxMimeParts` before it is read (`msgconvert`'s own disk use is bounded only by its 60 s timeout). CLI: `[general] max_email_size` (bytes), `max_mime_parts`, `max_header_lines` and `max_expanded_email_size`, also as `TSDMARC_GENERAL_MAX_EMAIL_SIZE` / `PARSEDMARC_GENERAL_MAX_EMAIL_SIZE` (and `..._MAX_MIME_PARTS`).
47. `getFilenameSafeString()` (sample file names and `filename_safe_subject`) also removes control characters (C0 including tab, DEL, C1) and bidi marks (U+061C, U+200E/F, U+202A–U+202E, U+2066–U+2069) before parsedmarc's 100-character and 100-UTF-8-byte cuts. ASCII names without control characters are unchanged. `saveOutput()` writes a sample whose name the filesystem still refuses as `sample.eml` (`sample (n).eml`) with a warning instead of failing the batch.
48. Parallel parsing: a worker thread that dies while running a job (out of memory, `process.exit()`, an uncaught error) fails only that job with `WorkerCrashedError` and is replaced; parsedmarc's `ProcessPoolExecutor` raises `BrokenProcessPool` for that job and every later one. Only a worker that fails while starting still breaks the pool (`BrokenProcessPool`). `parallelMap()` takes `onJobError(error, job)` to turn a failed job into a result instead of ending the iteration (the mailbox, mbox and CLI file paths use it, so the message or file is reported as invalid/failed: `Unexpected error parsing message UID <id>, treating it as invalid: <Error>: <message>` in a mailbox, `Skipping message <n>: ...` in an mbox; a mailbox retries timeouts and crashed workers instead, see 58), a `jobTimeout` in seconds after which the job fails with `JobTimeoutError` and its worker is replaced, and a `maxWorkerHeapMb`; both default to the task config's values (see 58), or no limit without a config.
49. Like parsedmarc 11.1.0's pool initializer, workers get the main thread's IP database path (as chosen or downloaded by `loadIpDb()`), IPinfo API token and PSL overrides (`initWorker()`); they also get the config's reverse DNS map when it is loaded, which parsedmarc's workers download again.
50. `sanitizeForLog()` (parsedmarc's `sanitize_for_log()`: every character for which Python's `str.isprintable()` is false becomes its `unicode_escape` form, `\r`, `\n`, `\t`, `\x1b`, `\u2028`, `\U000e0001`) is applied at parsedmarc's sites and at more: the text of every invalid-message warning in the mailbox and mbox loops, `Failed to parse <file> - <error>`, already-saved output warnings, output error lines, the `Could not write sample` warning and the debug dump of a legacy failure sample. The formats `configureLogging()` installs (`consoleFormat`, `fileFormat`) also pass the message of a logged error (`logger.exception()`, `log(..., { error })`) through it inside the stack, keeping the frames on their own lines; a stack that no longer contains the message, or a logged value that isn't an `Error`, is escaped whole. Python's `logging` writes the traceback as is, so a newline in a report field quoted by an error could add a forged line to the log file. Python's `isprintable()` is false for the Unicode categories Cc, Cf, Cs, Co, Cn, Zl, Zp and Zs except the space; tsdmarc uses the JS engine's Unicode tables (Node 24: Unicode 17, Python 3.14: 16), so a code point assigned after Unicode 16 is printable here and escaped by Python.
51. Zip members compressed with bzip2, LZMA or Zstandard (methods 12, 14, 93) are capped at 10 MiB decompressed (`MAX_DECOMPRESSED_SLOW_CODEC_SIZE`) instead of 100 MiB: their pure-TypeScript decoders are slow, and a 1.3 KB bzip2 member cost 2.7 s of CPU on an idle machine (10–14 s under load) to reach the 100 MiB cap; 0.3 s now. Over it, extraction fails with `Decompressed <codec> report exceeds the 10485760 byte limit for bzip2, LZMA and Zstandard zip members`. Deflate and gzip keep the 100 MiB cap; real DMARC reports use them (RFC 7489 asks for zip or gzip).
52. **Report limits** (parsedmarc has none; `0` disables each). `ParserConfig.maxNormalizedRecords` (default 250,000) caps the records of an aggregate report once its timespan is split into daily buckets: the count is computed before any bucket is built, and over it the report fails with `InvalidAggregateReport` (`Report needs too many records to normalize its timespan (max_normalized_records)`). A 0.7 KB email with a `date_range` from 1970 to 9998 and a high `count` builds 2.9 million records per `<record>`; Python uses memory until `MemoryError` (reported as an invalid report), while a full heap ends a Node process. A record only takes as many days as it has messages, so real reports stay far below it. Each day bucket is weighed by the output it produces: a row counts `max(1, (estimated size of the record + the report data every row repeats) / 2,048)` (`NormalizedRecordBudget`, which `appendParsedRecord()` takes instead of the plain number), so an ordinary row still counts one, while a record with thousands of `<dkim>` results, or a long `extra_contact_info`, spread over many days is refused before its buckets are built (an 82 KB report used to produce 200,000 rows of 73 KB each). Reports that are not normalized are not limited. `maxXmlDepth` (default 100,000) and `maxXmlNodes` (default 5,000,000 elements and attributes) are enforced while Expat reads an aggregate report, also on XML recovered from a malformed one; over either the report fails with `InvalidAggregateReport` (`Invalid XML: XML nests more than 100000 elements`, `Invalid XML: XML has more than 5000000 elements and attributes`) and no recovery is attempted (parsedmarc used 5.8 GB and 236 s on 100 MiB of `<a>`). `maxSmtpTlsReportSize` (default 10 MiB) rejects larger SMTP TLS JSON with `InvalidSMTPTLSReport` before parsing. `parseDate()` raises `DateParseError` for text over 1 MiB before tokenizing it (a 37 MB token took 54 s and 2.5 GB). `extractReportFromStream()` and `extractReportFromFilePath()` stop reading at `maxInputSize` (default 100 MiB) with `ParserError`; parsedmarc reads everything.
53. **SMTP TLS field types.** `parseSmtpTlsReportJson()` rejects with `InvalidSMTPTLSReport` what parsedmarc accepts and then fails on in the outputs, where one report stops its whole batch: `organization-name`, `report-id`, `policy-domain` and `result-type` that are not strings; `contact-info` that is not a string or a list of strings; `policy-string` and `mx-host-pattern` items that are not strings; session counts that are not integers or `null`; `start-datetime`/`end-datetime` that are not strings of at most 64 characters that `humanTimestampToDatetime()` parses; and optional failure-detail fields that are objects or lists (numbers pass, since the outputs store them as text).
54. **CSV rows.** `parsedAggregateReportsToCsvRows()` doesn't raise on a `<reason>` that passed parsing: a missing or empty `type` or `comment` is `none`, `<type lang="en">x</type>` is `x`, and a repeated `<comment>` is the `repr()` of the list (`['a', 'b']`); parsedmarc raises `KeyError`/`TypeError` after accepting the report, which ends the batch's CSV output. Each SMTP TLS policy starts its rows from the report's fields; parsedmarc reuses one dict, so a policy without `policy-string` or `mx-host-pattern` shows the previous policy's values, in CSV and in syslog and GELF, which read the same rows.
55. **Email parsing cost.** mail-parser's NFC normalization leaves text alone when it has a run of more than 128 consecutive combining marks (category `M`): ICU's canonical reordering is quadratic (80,000 marks took 26 s, 13 ms in CPython), and no language has such runs. uuencode that would decode to more bytes than its input stays undecoded, as Python leaves any invalid uuencode (`M\n` promises 45 bytes). `getaddresses()` costs linear time on nested groups and comments (Python copies at every level); past Python's recursion limit (491 nested comments; 982 nested groups, 979 in Python) it throws `RecursionError`, which `MailParser.fromString()` turns into `MailParserRecursionError` like `_parse_guarded()`, instead of a `RangeError` at a depth set by the JS stack. The parser reads a parent's `multipart/digest` content type once, when its headers are complete, instead of once per child: same output, linear cost (it took 30 s for 90,000 headers and 9,000 parts).
56. **mbox.** `getDmarcReportsFromMbox()` logs every `ParserError` as `Skipping message <n>: <name>: <error>` and goes on (except for an `EnrichmentError`, which ends the run, see 57), as the mailbox loop moves a message to Invalid. parsedmarc skips only `InvalidDMARCReport`, so one invalid attachment (a bare `ParserError` from `parse_report_email`) or an unreadable `Date` header raises out of `get_dmarc_reports_from_mbox()` and loses every report already parsed.
57. **Keepalive and enrichment failures stop a mailbox batch** (parsedmarc defects). A throwing `keepAlive` is rethrown as is by `parseAggregateReportXml()`, `parseAggregateReportFile()`, `parseReportEmail()` and `parseReportFile()`; parsedmarc reports it as `InvalidAggregateReport`/`ParserError`, so the message moves to the invalid folder or, with `delete`, is lost. When enrichment can't work for any report (a revoked IPinfo token, no readable IP database; see 66), parsedmarc files one-record reports as invalid and the others as parsed with no records. In both cases `getDmarcReportsFromMailbox()` now ends the batch with the error (an `EnrichmentError` also when it is in a report error's `cause` chain, sequentially or from a worker), like a failed fetch: nothing more is saved, moved or deleted, and the next run retries. Messages already found invalid keep their usual handling when parsing sequentially; in parallel they wait for the next run. `parallelMap()` keeps a throwing `heartbeat` apart from a failed job (`onJobError` doesn't see it). The IMAP and Maildir watch loops log the error and check again; Gmail and Microsoft Graph end the watch, and the one-shot CLI exits with status 1. An `EnrichmentError` (found with `findEnrichmentError()`) also ends an mbox run (`getDmarcReportsFromMbox()` rethrows it instead of skipping the message, see 56), and the CLI stops with exit status 1 when parsing a file hits one, before archiving any file or saving any report; before, the file went to `Invalid/` and each mbox message was skipped with a warning.
58. **Job timeouts and worker heap.** `ParserConfig.jobTimeout` (seconds, default 3600) limits parsing one email or file, and `maxWorkerHeapMb` (default 2048; `0` = the runtime's limit, about 4 GiB per worker) sets `resourceLimits.maxOldGenerationSizeMb` on each parsing worker (Deno applies it, Bun ignores it; V8 can still abort the whole process when one large allocation crosses it); `0` disables either, parsedmarc has neither. With `nProcs` 1 only a mailbox applies `jobTimeout`, at the next keepalive (every 20 records), so only time spent awaiting counts. A mailbox handles a timeout (`Timed out parsing message UID <id>: ...`) or a crashed worker (`Worker failed parsing message UID <id>: ...`) like an unsaved batch, never as invalid: the message stays for retry and moves to `<archive>/Unsaved` after `maxUnsavedRetries`, even with `delete` or `deleteInvalid`. An mbox skips such a message and the CLI reports the file as failed.
59. **Dedup and retry state.** `aggregateReportKey()` is parsedmarc's `_aggregate_report_dedup_key()` (org name, report ID and policy domain, ASCII case folded, as a JSON array), written without spaces (`JSON.stringify()`, where `json.dumps()` puts `, ` between the fields), and a key over 1,024 characters is stored as its SHA-256 (parsedmarc keeps it whole): every part comes from the sender and the key outlives parsing in the cache. Without `config`, `getDmarcReportsFromMailbox()` and `watchInbox()` keep seen reports per connection object, so a report seen in one mailbox isn't dropped (and archived) in another; pass one `config` to dedup across connections (the CLI keeps its process-wide cache, and the IP and reverse DNS caches stay module-wide). `ExpiringDict` drops expired entries on every `set()`, in amortized constant time (parsedmarc's only when the key is read again), and rewriting a key moves it to the back of the eviction order even when not full. `FAILED_SAVE_ATTEMPTS` keys include `MailboxConnection.mailboxIdentity` (`user@host:port` for IMAP, empty where message IDs are unique on their own), so IMAP accounts sharing folder names and UIDs don't share retry counters.
60. **Maildir as root.** When root drops to the Maildir's owner, the process also takes the Maildir's group as its only group (`setgroups`, `setgid`, then `setuid`); mailsuite keeps gid 0 and root's supplementary groups. If any of these calls fails (an owner uid not mapped in a user namespace, no `CAP_SETUID`/`CAP_SETGID`) or the runtime lacks one (Deno has no `process.setgroups()`), the `MaildirConnection` constructor throws `PrivilegeDropError` (`Failed to switch to uid <uid> and gid <gid> to access Maildir <path>: ... Run tsdmarc as the Maildir's owner (uid <uid>), or chown <path> to the user tsdmarc runs as.`), and the CLI exits with `Maildir Error`. mailsuite only warns (`Failed to switch uid to <uid>: ...`) and goes on as root. There is no option for the old behavior.
61. **Output files.** `appendJson()` writes to a temporary file in the same directory, flushes it and renames it over the old one (keeping mode, symlinks and, when permitted, the owner; anything but a regular file is written directly), so a crash or a full disk leaves the old content whole; the directory must be writable, and calls for one file run in turn within the process (other processes are not coordinated with). A corrupt or unreadable file, or one whose root is not an array, is moved to `<filename>.corrupt-<timestamp>` with a warning; parsedmarc overwrites it silently. Entries are written one at a time, and a file over 8 MiB already in `json.dump(indent=2)` layout only gets the new entries appended (the same bytes as a rewrite, without parsing it); one over 256 MiB in any other layout is moved aside instead of reformatted, and one report too long for a string raises `ValueError`. `saveOutput()` creates each sample `.eml` exclusively and takes the next ` (n)` suffix when the name exists, also across calls (random after ` (1000)`), so samples are never replaced; parsedmarc de-duplicates only within one call and overwrites older samples. `saveOutput()` builds the aggregate, failure and SMTP TLS CSV rows before writing anything: parsedmarc appends each JSON file before flattening its CSV, so a report the flattener fails on left its JSON entry written, and every retry of the batch added another copy. Now nothing is written for that call, and the CLI then writes the batch's reports one at a time (see 72), so only the failing report is left out.
62. **Syslog and GELF clients.** Each `SyslogClient` and `GelfClient` has its own `client.logger`; parsedmarc's share the process-wide `parsedmarc_syslog`/`parsedmarc_gelf` loggers, so with two clients every row goes to both servers, and a handler added to `getLogger('tsdmarc_syslog')`/`getLogger('tsdmarc_gelf')` no longer receives rows (syslog connection warnings still go there). Over TCP/TLS, Python's `SysLogHandler` keeps a dead socket forever and `SocketHandler` (GELF) drops messages silently, and the save "succeeds"; tsdmarc reconnects (TLS on every connection, `SocketHandler`'s 1–30 s back-off), sends the failed message once more, and throws `SyslogError`/`GelfError` from the save after draining when messages were still lost, so the batch is not archived (a retried batch can repeat rows). UDP stays best-effort.
63. **Splunk and webhook.** An SMTP TLS report whose `start-datetime` is not a date is sent to Splunk without `time` (Splunk uses the arrival time) and a warning names it; parsedmarc raises a non-`SplunkError` that loses the batch's SMTP TLS events and ends the run. HEC events are strict JSON: a reporter's `NaN`, `Infinity`, `-Infinity` or an overflowing number such as `1e999` (which `json.loads()` accepts in the optional SMTP TLS failure-detail fields) is sent as `null` (`pyJsonDumps()` option `nonFiniteAsNull`; the other outputs keep Python's output). parsedmarc's `json.dumps()` writes them bare, and the HEC rejects the whole request, so one report could fail every other event of the POST. `WebhookClientOptions.throwOnError` (default `false`: like parsedmarc, network errors are logged and HTTP error statuses ignored) throws network errors, timeouts and non-2xx responses, without the URL in the message; the CLI turns it on (see 72).
64. **Reverse DNS and IP lookups.** The `get_reverse_dns` debug line passes the address and the error through `sanitizeForLog()`. `getIpAddressInfo()` and `getIpAddressDbRecord()` validate `source_ip` first, raising the MMDB lookup's `ValueError` before any cache access, DNS query, IPinfo request or log line; parsedmarc validates only in the MMDB lookup, so with an API token a `source_ip` of `me` is sent to the API and accepted as the host's own network. `ParserConfig.maxLookupsPerReport` (default 100,000 source IPs that miss the cache), `maxFailedLookupsPerReport` (default 256 reverse DNS lookups that time out or fail; NXDOMAIN and NoAnswer don't count) and `maxLookupTimePerReport` (default 600 seconds spent on reverse DNS and IPinfo API lookups, since answers that aren't failures can still be slow) are counted per aggregate report (`0` = no limit; parsedmarc has none): past any of them, the remaining records keep IP database fields but get no reverse DNS or IPinfo API request, one warning is logged and those results aren't cached. Within a report, an IP whose result the shared cache doesn't keep (no PTR record and an ASN domain not in the map) is looked up once and its result reused for the report's other records; parsedmarc looks it up again for every record.
65. **Unusable IP database or IPinfo token.** `loadIpDb()` opens a download as MMDB before saving it, so a response that isn't one doesn't replace the cached copy (parsedmarc saves it). A database that can't be opened logs one warning and lookups fall back to the cached download, then the bundled copy; parsedmarc raises on each lookup.
66. **Enrichment errors.** `InvalidIPinfoAPIKey` and the new `IPDatabaseError` (no database can be opened; keeps `code`, such as `ENOENT`) extend the new `EnrichmentError`, which the per-record handler of `parseAggregateReportXml()` does not catch: the report fails with `InvalidAggregateReport` (and a mailbox stops, see 57). In parsedmarc that handler skips every record, so a report with several records returns `records: []` and is archived as parsed. A record that is bad on its own is still skipped.
67. **PostgreSQL connections.** libpq aborts when `channel_binding=require`, `require_auth`, `requirepeer`, `sslcertmode=require` or `gssencmode=require` can't be met; pg can't enforce them (it answers whatever authentication the server asks for), so these, also as `PGCHANNELBINDING`, `PGREQUIREAUTH`, `PGREQUIREPEER`, `PGSSLCERTMODE` and `PGGSSENCMODE`, refuse the connection (`<keyword>=<value> is not supported: pg cannot enforce it, so the connection was refused`; `require_auth` and `requirepeer` with any value), and `sslcrldir` refuses a TLS connection. Values that demand nothing (`channel_binding=disable`, `gssencmode=prefer`, ...) are still ignored with a warning. `sslcrl` (`PGSSLCRL`, default `~/.postgresql/root.crl`, applied only when the certificate is verified, as in libpq; a configured file must be readable) and `ssl_min_protocol_version`/`ssl_max_protocol_version` (`PGSSLMINPROTOCOLVERSION`, `PGSSLMAXPROTOCOLVERSION`) are honored. When `prefer` falls back to plain text the line is a warning, not a debug message, and recommends `sslmode=verify-full`; the default stays libpq's `prefer` so parsedmarc configurations keep working against servers without TLS. `sslmode` is never handed to pg, which treats `prefer`, `require` and `verify-ca` as `verify-full`. `PostgreSQLClientOptions.queryTimeout` (seconds, default 300, `0` = none, as in parsedmarc) bounds each statement with pg's `query_timeout`; on expiry the save fails with `PostgreSQLError` and the next save reconnects, so a hung statement can't block later saves and `close()`.
68. **PostgreSQL values.** So that one report can't fail every save of its batch (in parsedmarc each case fails with `PostgreSQLError`): a value that is not an IP in an `INET` column (`sending_mta_ip`, `receiving_ip`, `source_ip_address`) is stored as NULL with a warning; a count outside `INTEGER` (`message_count`, `successful_session_count`, `failed_session_count`) is clamped to the column's range with a warning (parsedmarc's schema can't hold it; the other outputs keep the exact integer); SMTP TLS `begin_date`/`end_date` forms dateutil reads but PostgreSQL doesn't (`12`, `+16:00`) are sent as `YYYY-MM-DD HH:MM:SS+00`, reading a value without an offset as UTC; and NUL, which PostgreSQL rejects in `text` and `jsonb`, is stored as U+FFFD. Any unexpected error during a save becomes `PostgreSQLError` (parsedmarc lets a `TypeError` escape and end the run); `PostgreSQLError` and `AlreadySaved` messages pass through `sanitizeForLog()`, because PostgreSQL quotes the rejected value, with the original error in `cause`.
69. **S3 overwrites.** `S3ClientOptions.preventOverwrite` (`[s3] prevent_overwrite`, default `false`, parsedmarc's behavior) sends every `PutObject` with `If-None-Match: *`. The key's hash covers only fields that aren't secret, so in parsedmarc a forged report that copies them replaces the real one. On `412` the existing object is read: an identical body is left alone (retries stay idempotent), a different one makes this report go to `<id>_<hash>-<sha256 of the JSON>.json` with the warning `s3://<bucket>/<key> holds a different <type> report with the same identifying fields; saving this one as <key>`, and `409 ConditionalRequestConflict` is retried up to three times. It needs `s3:GetObject`, and the first save of each client writes `<path>/.tsdmarc-conditional-write-check` twice: if the second write isn't refused (older MinIO and Ceph ignore the header), saving fails with `S3 service ignored If-None-Match ...` instead of overwriting silently.
70. **Log Analytics.** A report over 1,000,000 bytes of JSON (the SDK's chunk size and the service's request limit; the SDK sends a larger report alone and it is rejected) is left out with the warning `Report <id> not sent to Log Analytics: <n> bytes exceeds the 1000000-byte limit`, and the batch counts as saved. `publishResults()` tries all three streams and then throws the one error unchanged, or a `LogAnalyticsException` joining several; parsedmarc stops at the first. A retry uploads the streams that succeeded again.
71. **IMAP and Gmail.** Any error from a failed connection makes the IDLE loop reconnect (imapflow keeps the failed state, where Python's error happens once, and mailsuite ignores `IMAPClientError`s it doesn't recognize); `connect()` closes the session if `startIdle()` throws. mailsuite reconnects at once every time the IDLE connection drops; tsdmarc reconnects at once the first time, then waits 1 s, doubling up to 60 s, while connections keep failing within a minute of being made (a connection that lasted a minute resets the delay, and stopping the watch ends the wait), so a server that drops every connection no longer gets hundreds of reconnects a second. Without UIDPLUS, an EXPUNGE that imapflow reports as `false` is checked with `SEARCH DELETED`, and messages still flagged raise `IMAPClientError('EXPUNGE command failed')`. The Gmail OAuth redirect server answers 400 to an unparseable URL and to a `GET /` without the right `state`, and keeps waiting, so another local process or a web page can't end the flow (Python's server ends it at the first request, with `MismatchingStateError` for a foreign one); `error` is only read with the right `state` and goes through `sanitizeForLog()`. There is no `(mismatching_state)` `OAuthFlowError`: a flow that only gets wrong redirects waits for `timeoutSeconds` (forever by default).
72. **CLI runs.** Parsed input files are moved to `archive_directory` only after their reports reach every output; if any output fails, or the run exits first, that run's parsed files stay in place (with a warning) and the next run processes them again. parsedmarc archives each file right after parsing it, so a failed output left it archived and its reports unsaved. Files that fail to parse still go to `Invalid/` at once. Unknown errors from saving a report (failure and SMTP TLS reports, PostgreSQL, Splunk, file output), which end a parsedmarc process and, with a mailbox, repeat on every start, are recorded as output errors (`Elasticsearch exception Error: ...`, also `OpenSearch`, `PostgreSQL`, `Splunk HEC`, `File output`); the remaining reports and outputs go on and the batch counts as not saved. When file output fails for anything but a system error, each report is written on its own, so entries already written can repeat, as on any retry. A webhook that doesn't take a report (network error, timeout, non-2xx) is an output error too (`throwOnError`, see 63): its messages stay for a retry (then `Unsaved`), parsed input files are not archived and `fail_on_output_error` applies; in parsedmarc the message is archived or, with `delete`, deleted. The JSON of a batch is only built when printed (not with `silent`); over the runtime's longest string (about 512 MiB on V8) the batch is not printed, a `JSON output Error` is logged and the batch counts as not saved. The output errors `processReports()` returns or puts in the `fail_on_output_error` `ParserError`, the `ParserError`s the CLI logs and its archive and SMTP TLS `index_prefix_domain_map` lines go through `sanitizeForLog()`. A bare `DEBUG` that isn't a boolean (`DEBUG=*`, common with Node tools) is ignored with a warning instead of failing at startup; `TSDMARC_DEBUG` and `PARSEDMARC_DEBUG` stay strict. The Gmail deletion scope is checked again on a SIGHUP reload, against the scopes of the running connection (parsedmarc only checks at startup, so a reload turned deletion back on); adding the scope to the token file takes a restart.
73. **CLI settings not in parsedmarc.** `[general]`: `max_normalized_records`, `max_xml_depth`, `max_xml_nodes`, `max_smtp_tls_report_size`, `max_header_lines`, `max_expanded_email_size`, `job_timeout`, `max_lookups_per_report`, `max_failed_lookups_per_report`, `max_lookup_time_per_report`, `max_worker_heap_mb`. `[elasticsearch]` and `[opensearch]`: `max_indexes_per_report` (see 74). `[postgresql]`: `sslmode`, `sslrootcert`, `sslcert`, `sslkey` and `query_timeout`; the four TLS keys are ignored with `connection_string`, with an error in the log (they go in the string), while `query_timeout` applies either way. `[s3]`: `prevent_overwrite` (default `false`). All also work as `TSDMARC_*`/`PARSEDMARC_*` variables; `0` disables a limit and negative values are rejected. Unknown keys are still ignored, so parsedmarc files keep working.
74. **Elasticsearch and OpenSearch indexes.** One aggregate report spreads over at most 31 dated indexes (`maxIndexesPerReport` in `SaveOptions`; `0` removes the limit; it doesn't apply with `useDataStreams`, which writes one stream): parsedmarc names one index per day of a sender-chosen `date_range`, so a report of a few KB could create over 1,000 indexes and use up `cluster.max_shards_per_node`. Records past the limit go to the report's first index with their dates intact, with one warning. The save functions create indexes with `date_detection: false` and only the date fields declared (`date_range`, `date_begin`, `date_end`, `arrival_date`, `sample.date`); parsedmarc creates bare indexes, so the first document decides each type and `<report_id>2026-11-01</report_id>` maps it as `date`. Everything else stays dynamic and no `nested` mapping is added, as the dashboards need, except `sample.headers` of new failure indexes: `dynamic: false` with the headers the shipped dashboards use plus a few more (`INDEXED_SAMPLE_HEADERS`), each `text` with a `keyword` subfield as dynamic mapping would give, so senders' header names can't reach `index.mapping.total_fields.limit` (1,000) and get every later sample of that index rejected. Documents keep every header in `_source`; the others can no longer be searched. Existing indexes are not changed, and `createIndexes()` without `mappings` still creates bare ones. Concurrent saves to a new index no longer fail: parsedmarc checks `exists()` and then calls `create()`, so the second of two writers gets `resource_already_exists_exception` and its report fails halfway through its records (a retry then finds the saved part and raises `AlreadySaved`; see 76 for how tsdmarc resumes such a report); `createIndexes()` uses the index another writer created, and any other create error still raises `ElasticsearchError`/`OpenSearchError`. With `useDataStreams`, the index template of each stream carries the same mappings plus `@timestamp` (parsedmarc's maps only `@timestamp`, so the stream's fields are typed by the first document), its `_meta.description` names tsdmarc, and the stream set-up is remembered per client and template (parsedmarc: one set of names per process, cleared by `set_hosts()`). An alias that holds a stream's name is reported with the same clear error as a concrete index (`cannot create the data stream <name>: an index or alias with that name already exists`), where Elasticsearch's `illegal_argument_exception` reached parsedmarc's log as is.
75. **Elasticsearch and OpenSearch documents.** `From:` or `To: undisclosed-recipients:;` (no address) no longer aborts the save with `IndexError` outside any handler: the sample is saved without that header and it is left out of the duplicate search. Dots in sample header names become `_` (a `Subject.x` header would map `sample.headers.subject` as an object and reject every later text `Subject`). An element with children, which the parser leaves as an object, is written as `str()` in declared text and keyword fields and in the duplicate search's `match_phrase` (parsedmarc maps the field as an object and sends `domain` as the query's parameters). A `pct`, `sending_mta_ip` or `receiving_ip` its field can't hold is dropped with a warning instead of failing the save of the whole report (`failure_details_combined` keeps the original text); an invalid `source_ip_address` on a hand-built report still fails.
76. **Elasticsearch and OpenSearch searches and clients.** Duplicate searches use `dmarc_aggregate_prod-*` and `dmarc_aggregate-*` (same for `dmarc_failure`, `dmarc_forensic` and `smtp_tls`), where parsedmarc's `dmarc_aggregate_prod*`/`dmarc_aggregate*` also reach `dmarc_aggregate_production-...` and every other suffix, so a report saved under another suffix counted as saved. The search is `<name>-*,<name>`: the dated indexes plus the data stream of the same name (or an undated pre-5.0.0 index), so duplicates are caught across a switch to `useDataStreams`; `-v2` indexes still match. A failing duplicate search of a failure report raises `ElasticsearchError`/`OpenSearchError` like the other report types. An aggregate report is stored as one document per record, written one after the other, and parsedmarc takes any document the duplicate search finds as the whole report: after a write failed on record k, the retry raised `AlreadySaved`, the message was archived or deleted, and the records from k on were never stored. When the search finds fewer documents than the report has records, tsdmarc compares them with the report's own documents (dates, source IP, count, disposition, alignment, identifiers and the combined DKIM/SPF results; not the enrichment, which changes between attempts; `@tsdmarc/search-common/resume`) and, when each one is a record of this report, writes only the missing records, with the warning `Resuming aggregate report ID <id> from <org>: <n> of <total> records are already in Elasticsearch` (or `OpenSearch`). Otherwise, as in parsedmarc, the report counts as saved: every record is there, a document found isn't one of this report's records (another report with the same org, ID and domain), or the report has more than 9,999 records (the stored documents are read in one search page). With up to 9 documents found the hits of the duplicate search are compared as they are; with a full page of 10, one more search reads up to `records + 1` documents. Documents not yet refreshed (about a second after a write) aren't found, so a retry within that time can still write some records twice. The legacy `published_policy.fo` migration checks `_shards` on every page (`helpers.scan()` ignores it on a page without hits, so parsedmarc could delete the only copy), refreshes the target and compares document counts, keeping the original on a mismatch to retry at the next startup; OpenSearch also treats a bulk response without `items` as a failure. Responses keep integers beyond 2^53 exact (a custom `Serializer` in Elasticsearch, `enableLongNumeralSupport` in OpenSearch). OpenSearch turns on `disablePrototypePoisoningProtection`, since otherwise a stored sample with a `__proto__` header makes the duplicate search fail with `DeserializationError`. Besides the DSL-style `default` connection, which a later `setHosts()` redirects even for saves in progress, `createClient()` builds a client like `setHosts()` without registering it, and a `client` option (in `SaveOptions`, `MigrateIndexesOptions` and the fourth argument of `createIndexes()`) writes to it, so one process can write to several clusters; Elasticsearch keeps the `serverless` flag and bulk compatibility headers per client, and a client registered with `setDefaultConnection()` keeps its own settings.
77. **Loki.** The default `host` stream label uses `os.hostname()` (no synchronous FQDN lookup in JS; parsedmarc uses `socket.getfqdn()`), and the `timeout` bounds the whole push request rather than each phase, as for Splunk and the webhook.
