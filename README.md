# tsdmarc

[![npm](https://img.shields.io/npm/v/tsdmarc)](https://www.npmjs.com/package/tsdmarc) [![CI](https://github.com/helixnebulatech/tsdmarc/actions/workflows/ci.yml/badge.svg)](https://github.com/helixnebulatech/tsdmarc/actions/workflows/ci.yml) [![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](./LICENSE)

**A TypeScript library and CLI for parsing DMARC aggregate, DMARC failure and SMTP TLS reports. A 1:1 port of [parsedmarc](https://github.com/domainaware/parsedmarc).**

Mail receivers (Google, Microsoft, Yahoo, ...) send reports to the addresses a domain lists in its DMARC and TLS-RPT DNS records:

- **Aggregate reports** (DMARC `rua`, RFC 7489 / RFC 9990): daily XML summaries of which IP addresses sent mail using your domain, how much, and whether SPF, DKIM and DMARC passed.
- **Failure reports** (DMARC `ruf`, formerly "forensic", RFC 6591 / RFC 9991): a report about one message that failed DMARC, often with its headers.
- **SMTP TLS reports** (TLS-RPT, RFC 8460): JSON summaries of TLS successes and failures when other servers delivered mail to yours (MTA-STS, DANE).

They arrive zipped, gzipped or attached to emails, and they are hard to read by hand. tsdmarc reads them from files or mailboxes, enriches each source IP (reverse DNS, country, ASN, known sender name and type, base domain), and writes JSON/CSV or sends the results to Elasticsearch, OpenSearch, Splunk, PostgreSQL, Kafka, S3, Azure Log Analytics, Grafana Loki, syslog, GELF or a webhook. That shows who sends mail as your domain before you move your DMARC policy to `quarantine` or `reject`.

## Based on parsedmarc

tsdmarc is a 1:1 port of [parsedmarc](https://github.com/domainaware/parsedmarc) 11.2.1 (and of the parts of [mailsuite](https://github.com/seanthegeek/mailsuite) 2.3.4 it uses), by Sean Whalen and contributors.

- **Same output.** Every file in [`samples/`](samples) is parsed by both projects. The tests and the Node/Bun/Deno smoke tests compare tsdmarc's JSON and CSV with [reference fixtures](fixtures) generated by parsedmarc itself.
- **Same configuration.** The `tsdmarc` command reads parsedmarc's INI config files. Environment variables are `TSDMARC_{SECTION}_{KEY}`; `PARSEDMARC_*` names are accepted too (`TSDMARC_*` wins).
- **Same dashboards.** Index names, documents and field names are parsedmarc's, so its Kibana, OpenSearch Dashboards, Grafana and Splunk dashboards (copied in [`dashboards/`](dashboards)) work unchanged.

The deliberate differences are listed in [architecture/README.md](architecture/README.md#differences-from-parsedmarc). The main ones:

- **Security hardening.** Size limits on emails, MIME parts and decompression; credentials masked in more log and error messages than parsedmarc; capped HTTP response bodies; a private per-user download cache. See [Security](#security).
- **Elasticsearch 9 client.** `@tsdmarc/elasticsearch` uses `@elastic/elasticsearch` 9 (parsedmarc pins the v8 Python client) and sends `compatible-with=8` headers by default, so it works with Elasticsearch 8 and 9.
- **camelCase API.** Functions and report objects use camelCase (`parseReportFile`, `report.reportMetadata.orgName`). The outputs keep parsedmarc's snake_case keys.
- **JavaScript runtime details.** Async I/O, `worker_threads` instead of processes, imapflow, nodemailer and `fetch` instead of the Python libraries, with the behavior changes this implies (listed one by one).

## Quick start

### Library

```bash
npm install tsdmarc @tsdmarc/ipinfo-lite   # ipinfo-lite: optional, offline GeoIP
```

Parse a report file (aggregate XML, zip or gzip, SMTP TLS JSON, or a report email):

```ts
import { parseReportFile, pyJsonDumps, toSnakeCaseKeys } from 'tsdmarc';

const parsed = await parseReportFile(
  'google.com!example.com!1700000000!1700086399.zip',
);

if (parsed.reportType === 'aggregate') {
  for (const record of parsed.report.records) {
    console.log(
      record.source.ipAddress,
      record.count,
      record.policyEvaluated.disposition,
    );
  }
}

// The same JSON parsedmarc writes (snake_case keys)
console.log(pyJsonDumps(toSnakeCaseKeys(parsed.report), { indent: 2 }));
```

Process a mailbox and save the results as JSON and CSV:

```ts
import { IMAPConnection } from '@tsdmarc/imap';
import { getDmarcReportsFromMailbox, saveOutput } from 'tsdmarc';

const connection = await IMAPConnection.connect(
  'imap.example.com',
  'dmarc@example.com',
  { password: process.env.IMAP_PASSWORD },
);
try {
  const results = await getDmarcReportsFromMailbox(connection, {
    reportsFolder: 'INBOX',
    archiveFolder: 'Archive',
  });
  await saveOutput(results, { outputDirectory: 'output' });
} finally {
  await connection.close();
}
```

`MaildirConnection` comes with `tsdmarc`; Gmail and Microsoft Graph connections are in `@tsdmarc/gmail` and `@tsdmarc/msgraph`. See [`examples/`](examples) for runnable Node, Bun and Deno examples.

### CLI

```bash
npx @tsdmarc/cli --help
# or
npm install -g @tsdmarc/cli

tsdmarc samples/aggregate/*.xml           # parse files, print JSON
tsdmarc -o output/ report.xml.gz          # also write JSON and CSV files
tsdmarc -c config.ini                     # read a mailbox and send results where configured
```

A parsedmarc config file works as is. See [`examples/cli/`](examples/cli) and the [`@tsdmarc/cli` README](packages/cli/README.md).

## Runtime support

- Node.js ≥ 24, Bun and Deno 2. Tests run on Node 24 and 26; the built packages are smoke-tested on all three runtimes.
- ESM only, with TypeScript declarations. Only `node:*` modules that exist in all three runtimes.
- No native modules: zip, gzip, bzip2, LZMA and Zstandard decompression, the XML parser and the email parser are TypeScript.

## Security

Reports come from anyone who can send you email, so every input is treated as hostile:

- Decompression is capped at 100 MiB (10 MiB for the slow bzip2/LZMA/Zstandard zip members); emails are capped at 50 MiB and 10,000 MIME parts by default.
- XML is parsed without entity expansion (no XXE, no "billion laughs"), and deeply nested data is rejected.
- Regular expressions follow parsedmarc's anti-backtracking rules.
- Network calls have timeouts; TLS verification is on by default (also for GELF over TLS).
- IMAP and SMTP refuse to send credentials over a connection that wasn't upgraded with STARTTLS, as in parsedmarc 11.2.1, unless `starttls = False` is set (for a server on the same host only).
- Passwords and tokens are never logged; passwords in URLs are shown as `user:***@`. Prefer separate credential settings (`user`/`password`, `api_key`, `token`) to credentials in URLs.
- CSV cells that a spreadsheet would run as formulas are escaped, like parsedmarc.

To report a vulnerability, see [SECURITY.md](.github/SECURITY.md).
