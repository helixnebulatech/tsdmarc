# tsdmarc

DMARC report parser for Node.js, Bun and Deno: parses DMARC aggregate (RUA) reports, DMARC failure (RUF, formerly "forensic") reports and SMTP TLS (TLS-RPT) reports, enriches them with GeoIP, reverse DNS and base-domain data, and writes parsedmarc-compatible JSON and CSV.

This is the core package of [tsdmarc](https://github.com/helixnebulatech/tsdmarc#readme), a 1:1 TypeScript port of [parsedmarc](https://github.com/domainaware/parsedmarc) 11.2.1. Its output is checked against reference fixtures generated by parsedmarc itself.

## Install

```bash
npm install tsdmarc
# optional: the IPinfo Lite database (~25 MB), for GeoIP without downloads
npm install @tsdmarc/ipinfo-lite
```

Node.js ≥ 24, Bun or Deno 2. ESM only.

## Parse a report file

`parseReportFile()` accepts a path, bytes or a stream, and detects the format: aggregate XML (plain, zip or gzip), SMTP TLS JSON, or a report email (`.eml`, including failure reports).

```ts
import {
  parsedAggregateReportsToCsv,
  parseReportFile,
  pyJsonDumps,
  toSnakeCaseKeys,
} from 'tsdmarc';

const parsed = await parseReportFile('report.xml.gz', { offline: true });

if (parsed.reportType === 'aggregate') {
  const { reportMetadata, policyPublished, records } = parsed.report;
  console.log(reportMetadata.orgName, policyPublished.domain, records.length);
  console.log(parsedAggregateReportsToCsv(parsed.report));
}

// parsedmarc's JSON: snake_case keys, big integers written exactly
console.log(pyJsonDumps(toSnakeCaseKeys(parsed), { indent: 2 }));
```

`parsed.reportType` is `'aggregate'`, `'failure'` or `'smtp_tls'`, and `parsed.report` is typed accordingly (`AggregateReport`, `FailureReport`, `SMTPTLSReport`).

## Process a mailbox

`getDmarcReportsFromMailbox()` reads every message in a folder, parses the reports, and moves the messages to `Archive/Aggregate`, `Archive/Failure`, `Archive/SMTP-TLS` or `Archive/Invalid`. `MaildirConnection` is in this package; IMAP, Gmail and Microsoft Graph are in `@tsdmarc/imap`, `@tsdmarc/gmail` and `@tsdmarc/msgraph`.

```ts
import {
  getDmarcReportsFromMailbox,
  MaildirConnection,
  saveOutput,
} from 'tsdmarc';

const connection = new MaildirConnection('/var/mail/dmarc');
try {
  const results = await getDmarcReportsFromMailbox(connection, {
    archiveFolder: 'Archive',
    batchSize: 10,
  });
  // aggregate.json, aggregate.csv, failure.json, failure.csv,
  // smtp_tls.json, smtp_tls.csv
  await saveOutput(results, { outputDirectory: 'output' });
} finally {
  await connection.close();
}
```

`watchInbox(connection, callback, options)` keeps watching the folder (IMAP IDLE or polling) and calls `callback(results)` for each batch; pass `signal` (an `AbortSignal`) to stop it.

## Parser options

Every parsing function (`parseReportFile`, `parseReportEmail`, `parseAggregateReportXml`, `getDmarcReportsFromMailbox`, `watchInbox`, ...) accepts these options, or a `config` built once with `createParserConfig()`:

| Option | Default | Description |
| --- | --- | --- |
| `offline` | `false` | No DNS queries and no downloads. GeoIP still works with a local database. |
| `ipDbPath` | `null` | Path to an MMDB file (IPinfo, MaxMind or DB-IP). |
| `alwaysUseLocalFiles` | `false` | Use the bundled reverse DNS map and PSL overrides instead of downloading them. |
| `reverseDnsMapPath` / `reverseDnsMapUrl` | `null` | A custom reverse DNS map (file or URL). |
| `nameservers` | `null` | DNS servers (plain IPs, `https://` for DoH, `tls://` for DoT). `null`: Cloudflare. |
| `dnsTimeout` | `2.0` | DNS query timeout, in seconds. |
| `dnsRetries` | `0` | Retries after a DNS timeout or transient error. |
| `stripAttachmentPayloads` | `false` | Remove attachment payloads from failure report samples. |
| `normalizeTimespanThresholdHours` | `24` | Aggregate records spanning more hours are split into daily buckets. |
| `maxEmailSize` | 50 MiB | Largest email accepted (`0`: no limit). Not in parsedmarc. |
| `maxMimeParts` | `10000` | Most MIME boundary lines accepted (`0`: no limit). Not in parsedmarc. |
| `maxHeaderLines` | `100000` | Most header lines in an email, over all its parts (`0`: no limit). Not in parsedmarc. |
| `maxExpandedEmailSize` | 512 MiB | Most text, in characters (twice for text beyond Latin-1), re-serializing one email's parts may produce (`0`: no limit). Not in parsedmarc. |
| `maxNormalizedRecords` | `250000` | Most records of an aggregate report once split into daily buckets (`0`: no limit). Not in parsedmarc. |
| `maxXmlDepth` / `maxXmlNodes` | `100000` / `5000000` | Deepest nesting, and most elements and attributes, in an aggregate report's XML (`0`: no limit). Not in parsedmarc. |
| `maxSmtpTlsReportSize` | 10 MiB | Largest SMTP TLS report JSON (`0`: no limit). Not in parsedmarc. |
| `maxLookupsPerReport` / `maxFailedLookupsPerReport` / `maxLookupTimePerReport` | `100000` / `256` / `600` | Network lookups, failed reverse DNS lookups, and seconds of lookups, per aggregate report; past any of them, the remaining IPs only get the IP database (`0`: no limit). Not in parsedmarc. |
| `jobTimeout` | `3600` | Seconds one email or file may take to parse (`0`: no limit). Not in parsedmarc. |
| `maxWorkerHeapMb` | `2048` | Heap limit of each parsing worker, in MiB (`0`: the runtime's). Not in parsedmarc. |

## GeoIP

IP lookups use, in this order: `ipDbPath`; the database chosen by `loadIpDb()`; the `@tsdmarc/ipinfo-lite` package when installed. `loadIpDb()` (what the `tsdmarc` CLI calls at startup) downloads the latest IPinfo Lite database into a per-user cache directory and falls back to the cached or bundled copy when offline. `await configureIpinfoApi(token)` makes the IPinfo Lite REST API the primary source, falling back to the database on errors.

## API overview

All exports are named exports of `tsdmarc`. Types are exported too (`AggregateReport`, `FailureReport`, `SMTPTLSReport`, `ParsingResults`, `ParserConfig`, ...).

- **Parsing:** `parseReportFile`, `parseReportEmail`, `parseAggregateReportXml`, `parseAggregateReportFile`, `parseAggregateReportFromFilePath`, `parseFailureReport`, `parseSmtpTlsReportJson`, `extractReport`, `getDmarcReportsFromMbox`
- **CSV:** `parsedAggregateReportsToCsv`, `parsedFailureReportsToCsv`, `parsedSmtpTlsReportsToCsv` (and `...ToCsvRows`), `rowsToCsv`, `CsvDictWriter`
- **Files:** `saveOutput`, `appendJson`, `appendCsv`, `getReportZip`
- **Mailboxes:** `MailboxConnection` (base class), `MaildirConnection`, `getDmarcReportsFromMailbox`, `watchInbox`
- **Outputs without an SDK:** `HECClient` (Splunk), `LokiClient` (Grafana Loki push API; throws `LokiError` when a push fails, redirects are not followed), `SyslogClient`, `GelfClient`, `WebhookClient` (pass `throwOnError: true` to throw on network errors, timeouts and non-2xx responses instead of logging them, as the CLI does)
- **Enrichment:** `getIpAddressInfo`, `loadIpDb`, `configureIpinfoApi`, `loadReverseDnsMap`, `getReverseDns`, `queryDns`, `reverseNameFromAddress`, `getBaseDomain`
- **Log safety:** `sanitizeForLog`, `redactUrlCredentials` (masks URL passwords as `user:***@`), `maskNameserverSecrets`
- **Parallel parsing:** `parallelMap`, `parseReportFileTask`, `parseReportEmailTask` (worker threads)
- **Serialization:** `toSnakeCaseKeys`, `toCamelCaseKeys`, `pyJsonDumps`
- **Logging:** `logger`, `configureLogging`, `captureLogs`, Python-style levels (`DEBUG`, `INFO`, ...)
- **Errors:** `ParserError`, `InvalidDMARCReport`, `InvalidAggregateReport`, `InvalidFailureReport`, `InvalidSMTPTLSReport`, `EmailTooLargeError`, `EnrichmentError` (`InvalidIPinfoAPIKey`, `IPDatabaseError`), `PrivilegeDropError`, `SyslogError`, `GelfError`, `JobTimeoutError`, `WorkerCrashedError`

Backward-compatible aliases kept from parsedmarc (`parseForensicReport`, `InvalidForensicReport`, `parsedForensicReportsToCsv`) are exported as well.

## camelCase in, snake_case out

Report objects use camelCase keys (`report.reportMetadata.orgName`). Every output (JSON and CSV files, Splunk, Loki, syslog, GELF, webhook, and the `@tsdmarc/*` outputs) uses parsedmarc's snake_case names, so existing dashboards and queries keep working. Convert a report yourself with `toSnakeCaseKeys()`.
