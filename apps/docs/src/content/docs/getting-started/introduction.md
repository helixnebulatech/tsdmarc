tsdmarc is a TypeScript library and command-line tool for parsing DMARC reports. It is a **1:1 port of [parsedmarc](https://github.com/domainaware/parsedmarc) 11.2.1** (Python, by Sean Whalen and contributors) and of the parts of [mailsuite](https://github.com/seanthegeek/mailsuite) 2.3.4 that parsedmarc uses to talk to mailboxes and send email.

Used with Elasticsearch and Kibana, OpenSearch and Grafana, Splunk, PostgreSQL and Grafana, or Grafana Loki, it works as a self-hosted, open source alternative to commercial DMARC report processing services.

## Features

- Parses aggregate (rua) DMARC reports: the legacy draft and 1.0 schemas (RFC 7489) and the RFC 9990 schema of the final DMARC standard (RFC 9989).
- Parses failure (ruf) DMARC reports (RFC 6591 and RFC 9991; formerly called forensic reports).
- Parses SMTP TLS Reporting reports (TLS-RPT, RFC 8460).
- Reads reports from a mailbox over IMAP, the Microsoft Graph API, the Gmail API or a local Maildir, from mbox files, or from files on disk.
- Transparently handles zip and gzip compressed reports.
- Enriches every source IP address with reverse DNS, base domain, the name and type of the sending service, country and ASN.
- Produces consistent, normalized data structures, whatever the report schema.
- Writes simple JSON and CSV files, and can email the results.
- Sends the results to Elasticsearch, OpenSearch, Splunk, or PostgreSQL, for use with the premade dashboards.
- Sends the results to Apache Kafka, Amazon S3, Azure Log Analytics (Microsoft Sentinel), Grafana Loki, a Graylog (GELF) endpoint, a syslog server, or an HTTP webhook.

## Why a port?

parsedmarc is the reference open source DMARC report parser. tsdmarc brings it to the JavaScript ecosystem so that DMARC processing can live inside TypeScript applications and services, without a Python runtime:

- **Same results.** Parsing, enrichment, log messages, error types and output content follow parsedmarc. The test suite compares tsdmarc's output for every sample report against output generated by parsedmarc itself.
- **Same configuration.** The `tsdmarc` command reads parsedmarc's INI configuration file and accepts its `PARSEDMARC_*` environment variables.
- **Same dashboards.** JSON, CSV, Elasticsearch/OpenSearch documents, Splunk events and every other output use parsedmarc's snake_case field names, so the existing Kibana, OpenSearch Dashboards, Grafana and Splunk dashboards work.
- **TypeScript API.** Functions, options and report objects use camelCase (`parseReportFile()`, `report.policyPublished.domain`); Python keyword arguments become a single options object; anything that does I/O is `async`.

The deliberate differences are listed in [Migrating from parsedmarc](../../guides/migrating-from-parsedmarc/).

## Runtimes

tsdmarc is pure ESM and runs on **Node.js 24 or later**, **Bun** and **Deno**. It only uses `node:*` modules that the three runtimes provide; decompression (zip, gzip, bzip2, LZMA, Zstandard) and XML parsing are implemented in TypeScript, so no native module is needed.

## Packages

Like the Vercel AI SDK, tsdmarc is split into a small core and one package per integration, so you install only what you use:

| Package | Contents |
| --- | --- |
| `tsdmarc` | Parsing, enrichment (DNS, GeoIP, reverse DNS map), JSON/CSV output, Maildir, Splunk HEC, Loki, syslog, GELF, webhook, parallel parsing |
| `@tsdmarc/imap` | IMAP mailbox connection |
| `@tsdmarc/gmail` | Gmail API mailbox connection |
| `@tsdmarc/msgraph` | Microsoft Graph (Microsoft 365) mailbox connection |
| `@tsdmarc/smtp` | Send the results by email over SMTP |
| `@tsdmarc/elasticsearch` | Elasticsearch output (client v9) |
| `@tsdmarc/opensearch` | OpenSearch output |
| `@tsdmarc/postgres` | PostgreSQL output |
| `@tsdmarc/kafka` | Apache Kafka output |
| `@tsdmarc/s3` | Amazon S3 output |
| `@tsdmarc/loganalytics` | Azure Log Analytics output |
| `@tsdmarc/ipinfo-lite` | The IPinfo Lite database, for offline country and ASN lookups |
| `@tsdmarc/cli` | The `tsdmarc` command (depends on all of the above) |
